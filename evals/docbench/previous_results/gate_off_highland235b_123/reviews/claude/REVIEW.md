## 五、跨题问题：模型抄错文件 ID

**现象。** 工具参数里的附件 ID（`att_` 加 32 位十六进制）和模型输入中的真实 ID 对不上。抄错的调用全部返回错误：`file_unavailable` 42 次，`file_source_unavailable` 41 次，`file_access_unavailable` 12 次，`file_not_found` 4 次，其他 6 次。

| 批次 | 源码 | 视觉模型 | 带附件 ID 的调用 | 抄错 |
| --- | --- | --- | ---: | ---: |
| 上一轮首跑与两批补跑（09-10、09-11） | `81d7fd7` | 30B | 746 | 0 |
| router-binding-smoke（09-11） | `81d7fd7` | 30B | 2 | 0 |
| semantic-gate-off-smoke-5（09-14） | `b3e93d4` | 30B | 45 | 4 |
| 本轮（09-14） | `b3e93d4` | 235B | 703 | 105 |

**典型例子。** 63:2 的真实 `file_id` 是 `att_e6433bb71b2a4f1ea36cc92ce985bfa9`，`file_version_id` 是 `filever_1dd2d0e29a1c4d11a88d846de31b1a56`。模型写出的路径是 `att_e6433bb71b2a4f1` 接上 `1a88d846de31b1a56`，把前一个 ID 的前半段和后一个 ID 的后半段拼在了一起。之后 5 次调用都照抄这个错误路径，最后只交付了一句读取失败的说明。156:4 在同一轮里把同一个 ID 写出了 5 种不同的错法。

**原因排查（2026-09-15 补充）。**
- **不是本轮才要求模型抄 ID。** 上一轮冻结快照中，`tools/model_interface/arguments.py` 原样保留模型给出的参数（`deepcopy(arguments)`），`runtime/l1/model_view/projection.py` 注明"使用原生身份，不创建短引用表"；本轮的 `b3e93d4` 也一样。两轮都是模型直接抄写完整的 `att_` ID，Host 不做展开。
- **被测源码没有变。** 上一轮快照与 `b3e93d4` 在 `runtime/l1`、`tools/model_interface`、`tools/workspace`、`tools/documents`、`runtime/entry`、`model_io` 下逐字节相同（`model_io/tier_bindings.py` 只改了注释）。其余改动集中在会话历史索引、post-commit、API 和会话存储。本轮运行时 `source_sha256` 与 `b3e93d4` 干净检出不一致，但运行时的未提交改动只在 `evals/docbench`、`tests/evals`、`scripts` 下，`src/personagraph` 下没有。
- **两轮给模型的文件目录格式相同。** 几乎每次 attempt 的输入里都带着正确的 ID（上一轮 869/890 次，本轮 883/891 次），模型是看着正确的 ID 抄错的。
- **与视觉模型、语义门无关。** 用 30B 视觉的 `b3e93d4` 冒烟 run 已经出现抄错。两份运行特性配置唯一的差别是 `l1_semantic_verification_mode`，它只在候选答案通过机械检查后决定是否调用验证器，不改变模型输入。
- **上下文最干净时就会抄错。** 每题第一次带 ID 的工具调用中，本轮有 28/123 题（22.8%）已经抄错，大多是第一步的 `prepare_files`；上一轮是 0。
- **输入相同，模型行为却变了。** 按题配对（122 题）比较每题第一次 L1 attempt：输入 token 两轮相差都在 50 以内；输出却有 86 题变短、35 题变长，中位数从 248 降到 227.5；延迟中位数从 13.6 秒降到 11.6 秒。
- **结论：** 最可能的原因是端点 `deepseek-chat` 背后的模型或解码设置，在 09-11 到 09-14 之间发生了变化。轨迹没有记录后端模型版本和采样参数，所以无法从现有记录直接证实。两轮的输出都只有两百多 token，不像是开启了思考模式。

**影响。**

| 分组 | 题数 | Claude 判对 | L1 attempt 中位数 | 耗时中位数 | 输入 token 中位数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 有 ID 抄错 | 51 | 39（76%） | 9 | 245 秒 | 119,310 |
| 无 ID 抄错 | 72 | 67（93%） | 4 | 152 秒 | 48,643 |

这里有混杂因素：难题调用次数多，抄错的机会也多。但 17 道错题里有 12 道出现过 ID 抄错，其中 63:2、156:4 就是因为抄错才答不出来。

这个问题也解释了本轮成本上的反常。关闭语义门之后，本轮语义验证调用为 0（上一轮同 123 题有 147 次），用到视觉的题从 64 道降到 39 道，输入 token 从 14,137,803 降到 12,454,258（−11.9%）。**可逐题耗时合计反而从 31,426 秒升到 31,960 秒，L1 attempt 从 857 次升到 883 次，`prepare_files` 从 123 次升到 164 次**，多出来的调用基本对应 ID 抄错后的重试。
