## 阅读时的证据边界

以下是公开整理时的编者核对，不覆盖两份原评审及 JSON 中的意见。

1. **“关闭验证门造成退步”尚未证实。** CC 将 `108:2`、`165:0`（以及 `151:3`）
   的无依据内容交付归因于关门。旧轨迹中这三题的候选已经是最终交付内容，未发现验证反馈
   将错误候选修正为旧答案的证据。可以报告新答案变差，不能把差异直接归因于开关。
2. **抄完整 ID 不是本轮新增要求。** 两轮被测的 L1、工具接口及相关工具源码已有完整身份传递；
   122 对可配对的首次 L1 请求，其 system prompt 与工具目录相同。本轮 703 次带附件 ID 的
   工具调用中有 105 次抄错，涉及 51 题；同 123 题旧首跑为 674 次、0 次抄错。
   CC 的 684 指旧完整 125 题首跑，746 指旧首跑加补跑 133 次执行，分母不同。
   28 题在首次带 ID 的工具调用就出错，说明不只是长轨迹后期的问题。
   这些证据削弱“新增 ID 契约造成回退”的解释，但**不证明端点更换了后端模型**；
   后端模型/解码变化仍是 CC 的待验证假设，也不能证明开关与 VLM 对后续行为绝无影响。
3. **模型响应数不等于逻辑 attempt 数。** `156:4` 的 CC 原文与 telemetry 记为 25 次
   L1 attempt，实际上对应 25 次模型响应、24 个逻辑 attempt（含一次修复响应）。
   原归档数值保留，不应据此认定越过 24 次上限。
4. **视觉错读与输出不完整分开。** `17:8` 的错误表格行、`190:2` 的四人判断已出现在
   VLM observation 中；后者补足了 Codex 初稿尚未分层核定的部分。
   `32:1` 的视觉观察在 Figure 6 标题处结束，可确认内容不完整；未持久化 finish reason，
   不能断言必然由输出 token 上限造成。
5. **计数能力缺口不等于完全没有计数信息。** 项目已有物理页数等元信息及检索/读取能力；
   这些案例暴露的是全篇覆盖、计数口径和可靠工具使用不足。“模型没有计数工具”的概括
   不应外推为项目没有任何确定性计数信息。
6. **分歧题与争议集合不同。** CC 的三道分歧确实是 `66:3`、`80:5`、`144:3`；但 Codex
   JSON 的六道 `disputed_cases` 不含 `144:3`。CC 原文“三题都在双方争议清单”不准确；
   144:3 在 Codex 初稿中属于保留的真实问题，日期解释仍可交第三方仲裁。

工具失败例可直接从 [63:2 result](../runs/l1-gate-off-highland235b-123-20260914-a/cases/docbench-63-2/result.json)、

## 文件与来源身份

`REVIEW.md` 是对应评审原件的公开整理本，保留评分、理由和建议，补充整理说明，替换本机路径
及缺失链接；文件头给出私有原件 SHA-256。`case_reviews.json` 保留全部 123 行、原评分和评审
元信息；`publication` 给出原文件身份，`public_evidence` 链接本仓库同题的回答、轨迹和原评分。

已有 `result_sha256`、题目/参考/源 PDF 等哈希仍指向原件；`public_evidence` 的哈希指向公开
副本，所有路径相对于当前评审 JSON。不把私有原件哈希冒充公开文件哈希。
这些评审是事后分析，不是原始 run 输出；原题/参考答案字段、源 PDF 和完整私有原件未新增公开。
本次没有改动已公开的 result、trajectory、scoring，也没有新增 API 调用。
