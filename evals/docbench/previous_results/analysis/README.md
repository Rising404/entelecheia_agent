## 合并规则

1. 不改原始题目、参考答案、系统回复、裁判分数、Codex 复核列或本地评测档案。
2. 同一份公开 JSON 已原位补齐 CC 评分、来源哈希和声明元数据，
   `cc_review_status=archived_provisional` 表示“已归档、仍有争议”。
   原始运行与评分身份不变；后来归档的 review 元数据可更新，不能把档案完成理解为争议解决。
   最初的 pending 投影保留在 Git 历史，不再作为当前机器口径。
3. CC 源文件自述评审模型为 `claude-opus-5`；此处仅转述记录，不独立认证模型后端身份。
   CC 能看到 Codex 复核字段，因此不是盲评，也不是独立人类标注。
4. 本轮重新核对文件身份、逐题关联、总分和分项算术；没有重新调用模型、重跑 benchmark、
   重审全部 PDF 或恢复旧数据库。链路事实标明来自哪份存档审计，而非冒充本轮新实测。
5. 原报告中的实际题答、原文引句、模型笔记/裁判转述原句、私有绝对路径、Session/调用 ID
   及只能本机打开的链接不复制到公开副本。保留 benchmark case ID、评分、统计、
   机制解释和必要的分歧理由；这不是原档案的逐字镜像。
6. 不用后来的补跑过程解释首跑内部步骤，不把静态归档状态写成当前后台仍在运行；
   不用被测源码路径替代实际 source 指纹，也不据此认证迁移后的当前实现。
