# 两轮 DocBench 实验

两轮实验展示了 L1 文档任务的阶段性能力，也定位了影响交付的工程问题。**关闭验证门一轮单次完成全部 123 题的回答交付与后台收尾，正确率与前轮补跑合并结果接近；文本问答是表现最好的题型。**

[累计成绩](#按轮次累计比较) · [实际批次](#各实际批次的成绩) · [文档领域](#按文档领域比较) · [问题类型](#按问题类型比较) · [分析概要](#两轮实验的收获)

## 结果对比

两轮统一按 **123 题、123 份文档**比较。原选集中的 **`docbench:26:4`、`docbench:37:4`** 需要联网检索，超出本轮仅提供本地文档工具的范围，均从计分和比例分母中剔除；其他读取失败、链路失败和错答仍计入。

任务主模型与 DeepSeek 裁判均为 **DeepSeek Flash，未开启思考模式**；另两位裁判为 **Astra（Codex）**、**Opus 5（CC）**。

### 按轮次累计比较

下表始终使用同一组 123 题。两次补跑分别覆盖 3 道传输失败题和 5 道其他链路失败题；“补跑 3 题后”“补跑 8 题后”只替换对应题的结果，其余保留首跑，不增加分母。

| 阶段 | DeepSeek Flash | Astra | Opus 5 | 完成回答交付 |
| --- | ---: | ---: | ---: | ---: |
| 开启验证门 · 首跑 | 91 / 123（73.98%） | 99 / 123（80.49%） | 100 / 123（81.30%） | 115 / 123（93.50%） |
| 开启验证门 · 补跑 3 题后 | 93 / 123（75.61%） | 101 / 123（82.11%） | 102 / 123（82.93%） | 118 / 123（95.93%） |
| 开启验证门 · 补跑 8 题后（合并） | 96 / 123（78.05%） | 104 / 123（84.55%） | 105 / 123（85.37%） | 123 / 123（100.00%） |
| 关闭验证门 · 单次运行 | 97 / 123（78.86%） | 103 / 123（83.74%） | 106 / 123（86.18%） | 123 / 123（100.00%） |

开启验证门一轮的最终合并结果仍保留 6 题回答后的进程异常退出；关闭验证门一轮的后台收尾、进程退出均正常。

## 两轮实验的收获

- **开启验证门一轮：定位交付失败的来源。** 首跑 8 题未交付，分别为模型传输失败 3 题、验证失败 4 题、工具完成状态未确认 1 题；补跑后全部交付。分析进一步拆出了引用身份、历史回读、视觉结果完整性和回答后收尾等问题。
- **关闭验证门一轮：单次交付完整，答题质量总体接近。** 同时将视觉模型从 Qwen3-VL 30B 换为 235B 后，单次运行完成全部交付与收尾。相比前轮补跑合并结果，三位裁判判对题数分别变化 **+1、−1、+1**，主要进展体现在本次运行的交付完整性。
- **后续改进方向** 关闭验证门的文本问答正确率为 **92%、94%、94%**，多模态理解为 **76%、80%、88%**，元数据题三位裁判均为 **68%**。

  **和早期设想不同，尽管开启时验证门自身阻塞了一些应当被正常交付的文本、多模态题目，但对比关闭验证门的轮次，在unanswerable的题目上确实存在优势与提升。**

  全文统计、复杂图表、缺乏依据时的拒答，以及工具参数与身份传递，是后续重点。
